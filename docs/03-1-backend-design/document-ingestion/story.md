# 用户故事

| 故事编号 | PingCode 工作项编号 | 故事名称 | 故事说明 | 验收标准 |
| --- | --- | --- | --- | --- |
| DI-US-001 | CFD-108 | 上传单个 PDF 文档 | 作为工程师，我希望上传单个不超过 100MB 的 PDF，让系统为我创建可处理的文档记录并开始后台解析。 | 支持单文件 PDF 上传；非 PDF 或超限文件会被拒绝；上传成功后返回 `doc_id` 与 `uploaded` 状态。 |
| DI-US-002 | CFD-105 | 查看处理进度 | 作为工程师，我希望在等待过程中看到解析、切片、索引的实时状态和进度，便于判断何时可开始问答。 | 状态接口可返回阶段状态、进度百分比、页数和耗时；`ready` 前不会误显示可问答。 |
| DI-US-003 | CFD-110 | 预览上传中的文档 | 作为工程师，我希望文档上传成功后即可在右侧预览原始 PDF，而不必等待解析完成。 | 原始 PDF 保存成功后即可获取预览地址；解析未完成时也能打开预览；预览接口在锚点缺失时仍可返回 PDF 地址。 |
| DI-US-004 | CFD-107 | 取消未完成处理 | 作为工程师，我希望在处理时间过长或传错文件时取消当前处理，避免浪费时间。 | 处理中状态支持取消；取消后状态最终收敛为 `cancelled`；终态文档不能再次取消。 |
| DI-US-005 | CFD-111 | 生成可检索切片 | 作为问答服务的下游依赖方，我希望文档在就绪前已完成切片和向量化，以便按 `doc_id` 做严格检索。 | 切片优先按 Markdown 标题切分，失败时回退 token 策略；空切片会被过滤；只有全部 chunk 与 embedding 写入完成后文档才进入 `ready`。 |
| DI-US-006 | CFD-106 | 提供引用定位元数据 | 作为问答用户，我希望回答中的引用能跳转到文档对应页和段落位置，因此后端需要提前生成页码与锚点元数据。 | 每个稳定 chunk 都有 `page_num`、`title_path` 与 `anchor_id`；预览接口可返回这些锚点；无法生成 bbox 时至少支持页级定位。 |
| DI-US-007 | CFD-109 | 处理失败时给出明确原因 | 作为工程师，我希望在解析失败时看到稳定、可理解的错误原因，而不是内部异常堆栈。 | 状态接口返回 `error_code` 和用户可理解的 `error_message`；加密文件、损坏文件、超时等场景有明确失败码。 |
