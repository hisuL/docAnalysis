# 技术设计阶段，pingcode-skill的 Used Guide

## 什么时候用
- 当story.md里的用户故事已经确定，并且准备同步到（新增-更新）pingcode系统里使用

## 怎么用
- 检查pingcode-skill是否存在，如果没有,跳过pingcode同步操作，提示用户检查pingcode-skill的状态。
- 先按照pingcode-skill的要求，检查是否能正常查到pingcode系统里的项目和模块，如果没有，打印提示信息提醒用户检查pingcode系统的状态和权限配置，跳过pingcode同步步骤，继续后续操作。
- 从AGENTS.md或者CLAUDE.md里获取PINGCODE的项目ID，如果没有选择或者查询不到，主动查询pingcode系统里所有的项目列表，提示用户选择一个项目。
- 解析story.md里的用户故事定义，转换成pingcode系统要求的工作项。工作项类型为"用户故事"，如果是新增故事默认工作项状态为"打开"。否则保持原有工作项状态不变。
- 调用pingcode系统的接口，将转换好的工作项依次同步到指定的项目里,并更新story.md里用户故事定义的pingcode编码为对应的工作项ID
- 导入完成后，输出导入结果，包括成功的工作项数量和失败的工作项数量，以及失败的工作项列表和错误信息
- 如果导入过程中发生任何错误，跳过pingcode同步操作，输出错误信息，并提示用户检查用户故事定义和pingcode系统的状态

## 不建议用的场景
- story.md里的用户故事定义还不稳定，频繁变动，尚未准备好同步到pingcode系统里使用
- 没有正确配置环境变量，无法访问pingcode系统，或者没有权限访问指定的项目
- 需要对用户故事定义进行大量修改和调整，尚未准备好进行批量导入到pingcode系统
