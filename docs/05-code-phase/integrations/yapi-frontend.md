# YAPI Frontend Guide

> 面向前端开发的 YAPI 使用规范。YAPI 负责“核对契约、获取 Mock、辅助联调”，不承担任务管理职责。

## 什么时候使用
- 当前要实现的前端能力边界已经明确后
- 需要确认接口路径、字段、示例、错误码时
- 需要基于 Mock 推进前端开发或联调前演练时

## 使用前提
- 先确认对应模块在 YAPI 中已有可读取的接口定义
- 若需要理解业务语义、状态机或设计边界，再补读 `docs/03-1-backend-design/` 与 `docs/03-2-frontend-design/`

## YAPI 的定位
- 编码阶段的主读取源，用于接口路径、请求方法、字段结构、错误码、示例和 Mock
- 适合作为前端 Agent 的默认接口读取入口，尤其适合通过开放平台接口自动读取
- 不替代 `03-1` / `03-2` 中的业务语义、状态机、设计意图和边界说明

## 前端怎么使用
1. 先明确当前要实现的前端能力范围，再进入 YAPI
2. 直接以 YAPI 中的接口定义作为路径、字段、错误码和示例的主读取源
3. 仅通过统一请求层或配置层接入 Mock 地址
4. 若设计语义、状态机或交互边界不清，再回看 `03-1` / `03-2`
5. 确认 Mock 数据结构与当前 YAPI 定义一致后，再推进页面开发
6. 联调前再次确认 YAPI 与后端真实实现是否一致

## Mock 使用边界
- Mock 用于开发、调试、演示和联调前验证
- 不把 YAPI Mock 返回成功当作真实契约一定正确
- 不在组件内直接拼接 Mock URL
- 不把 Mock 地址写进正式环境逻辑
- 不用 Mock 掩盖字段缺失、错误码缺失或状态机不明确的问题

## 发现冲突时怎么做
1. 标记冲突的接口、字段、错误码或示例
2. 判断是 YAPI 未同步，还是 `03-1` / `03-2` 未回写
3. 若涉及业务语义、状态机或交互边界，再对照 `docs/03-1-backend-design/` 与 `docs/03-2-frontend-design/`
4. 评估影响范围和当前阻塞点
5. 记录到 `docs/05-code-phase/front/CHANGELOG.md`
