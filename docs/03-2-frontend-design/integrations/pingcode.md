# PingCode Design Sync Guide

> 面向 03-2 前端详细设计阶段的 PingCode 使用说明。本文只处理“设计阶段如何拆任务、如何同步管理边界”，不覆盖编码阶段的取单与实现流程。

## 文档定位

- 03-2 关注：
  - 如何把用户故事拆成适合录入 PingCode 的前端能力闭环任务
  - 如何把设计文档路径、依赖和验收标准同步到工作项
  - 如何在设计变更后识别需要同步更新的管理项
- 本文不负责：
  - 编码阶段如何认领任务
  - 代码实现规则
  - 联调完成后的状态回写细则

## 什么时候使用

- 03-2 已完成模块范围收敛，需要把设计结果同步到 PingCode 时
- 需要把用户故事转换为可管理的前端工作项时
- 设计发生变更，需要判断哪些 PingCode 工作项需要更新时

## 设计阶段的 PingCode 定位

- PingCode 服务于管理、优先级、协作、验收和跟踪。
- PingCode 不是 AI Agent 的最细执行步骤清单。
- 03-2 输出到 PingCode 的任务，应保持“能力闭环粒度”，而不是实现动作粒度。

## 标准流程

1. 先完成模块级 `design-plan.md`，以及按复杂度需要的 `page-design.md` / `component-design.md`
2. 基于用户故事和交互闭环生成 `work-item-breakdown.md`
3. 从 `work-item-breakdown.md` 中提取适合录入 PingCode 的工作项
4. 为每个工作项补充范围、依赖、验收标准和设计文档引用
5. 如设计后续变更，检查是否需要同步更新对应工作项描述、依赖或验收标准

## 任务拆分规则

- 一个 PingCode 工作项应对应一个可独立验收的前端能力闭环。
- 一个工作项内允许同时覆盖页面、组件、状态、接口接入、测试和异常处理。
- 不按“接接口”“补 loading”“补按钮”“补样式”“补测试”默认细拆成独立 PingCode 任务。
- 只有涉及跨角色协作、依赖阻塞、缺陷跟踪、版本风险或独立验收边界时，才继续细拆。

## 工作项描述最低要求

- 标题
  - 统一加前缀 `[前端]`
- 范围
  - 说明该能力闭环覆盖哪些页面、组件或流程
- 前置依赖
  - 说明依赖的上游能力、接口或前序工作项
- 验收标准
  - 至少包含主流程、异常态和完成定义
- 设计引用
  - 至少指向对应模块的 `design-plan.md`
  - 若存在 `page-design.md` / `component-design.md`，再补充对应引用

## 变更后何时需要同步 PingCode

以下变化默认应检查 PingCode 是否需要更新：
- 模块范围变化
- 页面主流程变化
- 验收标准变化
- 依赖关系变化
- 工作项边界变化

以下变化通常不需要单独改 PingCode：
- 文案微调
- 纯实现细节重构
- 不影响验收边界的小型样式修正

## 不该怎么做

- 不把设计阶段的内部执行步骤都写成 PingCode 子任务
- 不把 PingCode 反过来当作 03-2 设计的唯一来源
- 不因为管理方便就把一个完整能力拆成大量失去上下文的小任务
