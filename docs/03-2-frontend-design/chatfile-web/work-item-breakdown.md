# 工作项拆解

## 1. 范围

本文件将 `chatfile-web` 模块的前端详细设计拆成可同步到 PingCode 的用户故事与任务。

拆分原则：
- PingCode 中的任务粒度优先服务于管理、协作、验收和进度跟踪。
- 每个任务保持能力闭环，允许 AI Agent 在认领后自行生成内部执行步骤。
- 不把“接接口、补按钮、补样式、补 loading、补测试”等实现步骤默认拆成独立 PingCode 工作项。
- 只有涉及跨角色协作、依赖阻塞、缺陷跟踪、版本风险或独立验收边界时，才继续细拆。

拆解依据：
- `design-plan.md`
- `page-design.md`
- `component-design.md`
- `docs/01-prd/PRD.md`
- `docs/01-prd/ChatFile_interactive.md`
- `docs/03-2-frontend-design/integrations/pingcode.md`

## 2. 用户故事地图

### Story A. 上传并进入可问答状态

用户故事：
- 作为使用者，我希望上传一份 PDF 并清楚看到处理进度，这样我能知道何时可以开始提问。

验收标准：
- 支持拖拽与点击上传
- 支持格式和大小校验
- 展示上传进度和四阶段处理状态
- 处理完成后进入 ready 工作台
- 处理失败时给出稳定失败原因和重传入口

任务拆解：
- `[前端] 文档上传与处理状态工作流`
  - 范围：上传空态、拖拽/点击上传、文件校验、上传进度、处理步骤、ready/failed/cancelled 回路、刷新后状态恢复
  - 依赖：无
  - 验收：从无文档到 `ready/failed` 的主链路完整，`ready` 前输入禁用，失败和取消路径有明确反馈

### Story B. 在工作台中提问并查看流式回答

用户故事：
- 作为使用者，我希望在文档 ready 后立即提问，并看到带引用的流式回答，这样我可以快速确认答案来源。

验收标准：
- ready 前输入框禁用
- 支持流式回答和中断
- 支持拒答与失败降级
- 支持最近 10 轮历史
- 输入区支持快捷键

任务拆解：
- `[前端] 对话消息流与输入控制`
  - 范围：消息列表、历史消息恢复、流式问答、生成中状态、stop 中断、输入框、发送按钮、更换文档入口、快捷键、拒答和失败重试
  - 依赖：文档进入 `ready`
  - 验收：`idle -> retrieving -> generating -> completed/interrupted/failed` 状态完整，快捷键行为符合设计，断流后存在可恢复路径

### Story C. 查看 PDF 并根据引用跳转高亮

用户故事：
- 作为使用者，我希望点击回答中的引用后，右侧 PDF 能自动定位并高亮相关段落，这样我能快速核对原文。

验收标准：
- 工作台默认 40/60 分栏
- 支持拖拽调整比例
- 支持预览折叠和自动展开
- 支持页码导航、缩放、目录
- 支持引用跳页和高亮

任务拆解：
- `[前端] ChatWorkspace 布局与 PDF 预览联动`
  - 范围：40/60 左右分栏、拖拽调整、右侧预览折叠/展开、PDF 预览、页码导航、缩放、目录占位、预览失败降级、引用触发自动展开
  - 依赖：文档进入 `ready`
  - 验收：工作台布局稳定，PDF 具备可用预览能力，预览失败不阻断问答主流程
- `[前端] 引用跳转高亮与回答反馈`
  - 范围：回答中的引用展示、点击引用跳页、高亮、点赞/点踩、标签与补充说明、提交结果反馈
  - 依赖：对话消息流与 PDF 预览基础能力已具备
  - 验收：引用可驱动右侧预览定位，高亮缺失时有降级方案，反馈动作可提交并可重试

### Story D. ready 后获得欢迎引导并提交反馈

用户故事：
- 作为使用者，我希望文档 ready 后先看到摘要和推荐问题，并能对 AI 回答做点赞或点踩反馈，这样我能更快开始使用并反馈质量。

验收标准：
- 文档 ready 且无消息时显示摘要与推荐问题
- 点击推荐问题自动发送
- 每条 AI 消息支持点赞/点踩
- 点踩可补充标签和说明
- 提交成功后有确认反馈

任务拆解：
- `[前端] 欢迎态与推荐问题首问体验`
  - 范围：ready 且无消息时的欢迎态、文档摘要、推荐问题、点击推荐问题直接发起首问、欢迎接口失败时的降级
  - 依赖：文档进入 `ready`，对话发送链路可用
  - 验收：会话为空时正确展示欢迎态，推荐问题可发起首轮问答，欢迎接口失败不阻断正常问答
- `[前端] chatfile-web 联调验收与测试闭环`
  - 范围：YAPI/真实接口契约核对、Mock 造数、API 对齐修正、集成测试、E2E 验证、测试结论沉淀、缺陷回写 PingCode
  - 依赖：主要能力开发完成
  - 验收：上传 -> ready -> 首问 -> 引用 -> 反馈主流程走通，关键状态覆盖完整，并能输出可追踪的测试结论

若 PingCode 允许补充子任务描述，应补充：
- 设计文档路径
- 范围与依赖
- 验收标准
- 负责人：`赵帅更`
- 类别：`前端开发`

- 单独的“接接口”
- 单独的“补 loading / error / empty”
- 单独的“补快捷键”
- 单独的“补样式”
- 单独的“补测试”

以上内容默认作为 Agent 在工作项内部自行展开的执行步骤。
